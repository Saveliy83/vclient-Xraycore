# Архитектура

## Поток пользовательского трафика

```text
+------------------+
| Приложение       |
| браузер / curl   |
+--------+---------+
         |
         | SOCKS5 127.0.0.1:1080
         | или HTTP 127.0.0.1:1081
         v
+------------------+
| Inbound Xray     |
| SOCKS / HTTP     |
+--------+---------+
         |
         v
+------------------+       +------------------+
| Router Xray      |------>| direct / block   |
| rules + default  |       +------------------+
+--------+---------+
         | outboundTag=proxy
         v
+------------------+
| VLESS outbound   |
| UUID / flow      |
+--------+---------+
         |
         v
+------------------+
| Transport        |
| TCP / WS / gRPC  |
| XHTTP / другие   |
+--------+---------+
         |
         v
+------------------+
| VLESS-сервер     |
+------------------+
```

На старте CLI получает профиль из `-link`, `-config` или `-sub-url`, проверяет
его и преобразует вместе с необязательными настройками маршрутизации и DNS в
JSON-конфигурацию Xray. `internal/core` загружает JSON через API подключённой
библиотеки Xray-core и запускает экземпляр ядра. Локальные приложения
подключаются только к настроенным inbound. Пользовательские правила
маршрутизации обрабатываются до правила по
умолчанию, отправляющего TCP/UDP в `proxy`.

Подписка кэшируется отдельно в `cache/subscription.json`; файл содержит полный
список разобранных профилей. Логгер пишет в stdout и, если задан `-log-file`,
в файл. Дополнительное описание чувствительных данных приведено в
[security.md](./security.md).
