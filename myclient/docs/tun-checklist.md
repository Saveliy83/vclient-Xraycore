# Чек-лист полного туннеля Windows (TUN)

Проверки маршрутов и IPv6 выполняются только на тестовой виртуальной машине,
от имени администратора и с сервером, которым вы управляете. До начала
проверьте, что у вас есть консольный доступ или иной способ восстановления
сети. Ни один ручной VM-сценарий в этом чек-листе не считается выполненным,
пока оператор явно не зафиксировал результат.

## Статус проверок

Используются только три отметки:

- **выполнено автоматически** — команда или unit-тест завершились успешно;
- **выполнено вручную на VM** — сценарий завершён на тестовой Windows VM, и
  результат внесён оператором;
- **не выполнено** — команда/сценарий ещё не запускались либо результат не
  подтверждён.

| Проверка | Статус |
| --- | --- |
| `gofmt -l cmd internal` | выполнено автоматически |
| `go vet -tags ci ./...` | выполнено автоматически |
| `go test -tags ci ./...` | выполнено автоматически |
| `go build -tags ci ./...` | выполнено автоматически |
| `go test -race -tags ci ./...` с `CGO_ENABLED=1` и GCC | не выполнено |
| Windows AMD64 compile-only тесты `internal/tunmode` | выполнено автоматически |
| GUI release `build.ps1 -Target gui` с проверенной Wintun DLL | не выполнено |
| Включение/выключение, состояние маршрутов и DNS на VM | не выполнено |
| `BlockIPv6` on/off и восстановление физических адаптеров на VM | не выполнено |
| Recovery после завершения процесса и отключение сервера на VM | не выполнено |
| Проверка без прав администратора, конфликтов VPN и sleep/resume на VM | не выполнено |

## Эталонное состояние до теста

Отключите остальные VPN, откройте PowerShell от администратора и сохраните
состояние до изменений. Запишите имя физического адаптера, его IPv4-шлюз, DNS
и состояние IPv6 binding:

```powershell
route print | Out-File "$env:TEMP\vclient-routes-before.txt"
ipconfig /all | Out-File "$env:TEMP\vclient-ipconfig-before.txt"
Get-NetAdapter -Physical | ForEach-Object {
    Get-NetAdapterBinding -Name $_.Name -ComponentID ms_tcpip6 |
        Select-Object Name, Enabled
}
```

Обычный IPv4 default route и исходные DNS зависят от тестовой сети. Не
продолжайте, пока не знаете, как вручную восстановить подключение.

## Сценарии на тестовой VM

У каждой ручной проверки исходный статус — **не выполнено**. После выполнения
запишите фактический результат и только затем измените статус на **выполнено
вручную на VM**.

| Сценарий | Что проверить | Статус |
| --- | --- | --- |
| Включение TUN | Включить «Весь трафик», подключиться, открыть `https://ifconfig.me` в Firefox без прокси. | не выполнено |
| Таблица маршрутов | `route print` показывает ровно добавленные маршруты из recovery state: IPv4 `0.0.0.0/1`, `128.0.0.0/1`, host route(ы) сервера и local bypass routes, если включены. Новых IPv6-маршрутов нет. | не выполнено |
| DNS TUN | `ipconfig /all` показывает заданные DNS на виртуальном адаптере; исходные настройки адаптера сохраняются в recovery state. | не выполнено |
| Выключение | После Disable split-default и защитные маршруты удалены; исходный IPv4 default route и DNS доступны. | не выполнено |
| `BlockIPv6=true` | На всех физических адаптерах, которые были включены до VPN, IPv6 binding выключен; IPv6 маршруты через TUN не добавлены. После выключения исходное состояние каждого адаптера восстановлено. | не выполнено |
| `BlockIPv6=false` | IPv6 binding физических адаптеров не меняется, IPv6-маршруты не добавляются; IPv6 остаётся вне VPN и может направляться напрямую. | не выполнено |
| Ошибка второго адаптера | На отдельной VM искусственно/инструментально проверить, что ошибка выключения второго адаптера восстанавливает уже изменённый первый адаптер и возвращает ошибку. | не выполнено |
| Аварийное завершение | Завершить vclient через диспетчер задач, запустить его снова и проверить recovery маршрутов, DNS и IPv6 по `route print`, `ipconfig /all`, `Get-NetAdapterBinding`. | не выполнено |
| Обрыв сервера | Остановить контролируемый сервер; после трёх последовательных неудачных health-check с интервалом 10 секунд приложение пытается отключить TUN и восстановить прямой доступ. | не выполнено |
| Нет прав администратора | Запустить без elevation: включение TUN должно завершиться понятной ошибкой без изменения состояния сети. | не выполнено |
| Прокси-интерфейсы | Убедиться, что SOCKS5 `127.0.0.1:1080` и HTTP `127.0.0.1:1081` доступны параллельно с TUN. | не выполнено |
| Сон/конфликт VPN | Проверить sleep/resume и работу рядом с другим VPN отдельно; результат зависит от драйверов и сети. | не выполнено |

Снимите состояние после каждого сценария и сравните с исходным:

```powershell
route print | Out-File "$env:TEMP\vclient-routes-after.txt"
ipconfig /all | Out-File "$env:TEMP\vclient-ipconfig-after.txt"
Compare-Object (Get-Content "$env:TEMP\vclient-routes-before.txt") (Get-Content "$env:TEMP\vclient-routes-after.txt")
Compare-Object (Get-Content "$env:TEMP\vclient-ipconfig-before.txt") (Get-Content "$env:TEMP\vclient-ipconfig-after.txt")
Get-NetAdapter -Physical | ForEach-Object {
    Get-NetAdapterBinding -Name $_.Name -ComponentID ms_tcpip6 |
        Select-Object Name, Enabled
}
```

## IP Helper API

Создание, перечисление и удаление маршрутов выполняются IP Helper API.
PowerShell используется только для чтения/установки DNS и чтения/переключения
IPv6 binding. После Enable обязательно сверяйте через `route print`, что
добавлены ожидаемые IPv4-маршруты и нет лишних записей; сравните их с
`added_routes` и `protect_routes` в `%APPDATA%\vclient\tun-state.json`.

## Известные ограничения и ручное восстановление

- Kill switch **не реализован**. При сбое очистки интернет может остаться
  направленным через туннель. Ошибка Disable содержит оставшиеся маршруты.
- Если остались IPv4 split-default маршруты, сначала проверьте их владельца в
  `route print`, затем в PowerShell от администратора выполните:

  ```powershell
  route delete 0.0.0.0 mask 128.0.0.0
  route delete 128.0.0.0 mask 128.0.0.0
  route print
  ```

  Не удаляйте маршруты, если они принадлежат другому VPN.
- Если после аварии IPv6 binding физического адаптера остался выключенным,
  восстановите его по записанному до теста имени адаптера:

  ```powershell
  Enable-NetAdapterBinding -Name "<адаптер>" -ComponentID ms_tcpip6
  ```

  Если исходное состояние было выключено, не включайте binding; восстановите
  именно исходное значение.
- Recovery идентифицирует процесс по паре PID и времени запуска (FILETIME).
  Повторно использованный PID с другим временем запуска считается
  осиротевшим состоянием и запускает восстановление.
- При `BlockIPv6=true` IPv6 binding временно отключается на физических
  адаптерах, исходное состояние сохраняется до изменения и восстанавливается
  при Disable/recovery. IPv6 не проходит через TUN. При `BlockIPv6=false`
  IPv6 оставлен включённым и может идти напрямую вне VPN.
- Health-check зависит от доступности `api.ipify.org` через локальный SOCKS:
  три последовательные ошибки с интервалом 10 секунд запускают отключение.
- Конфликты с другими VPN, сон/пробуждение, внешние сетевые фильтры и смена
  физических адаптеров требуют отдельной проверки на VM.
