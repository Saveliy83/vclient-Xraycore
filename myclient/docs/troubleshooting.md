# Диагностика неисправностей

## `go: command not found`

Go не установлен или каталог с `go.exe`/командой `go` отсутствует в `PATH`.
На Windows установите Go с [go.dev/dl](https://go.dev/dl/), проверьте наличие
каталога `C:\Program Files\Go\bin` в системной переменной `Path` и перезапустите
PowerShell. Проверьте:

```powershell
go version
```

В Linux установите Go и добавьте каталог установки в `PATH`, затем откройте
новую оболочку и проверьте `go version`.

## `connection refused` на порту 1080

Убедитесь, что vclient запущен и не завершился из-за ошибки профиля или
конфигурации, а локальный адрес совпадает с `-listen-socks`. Возможно, порт
занят другим процессом.

Windows:

```powershell
netstat -ano | findstr 1080
```

Если порт используется, завершите конфликтующий процесс осознанно либо задайте
другой адрес через `-listen-socks`, затем укажите тот же адрес в клиентском
приложении.

## Ошибка TLS handshake

- Проверьте, что `sni`/`tls.server_name` совпадает с именем, ожидаемым сервером.
- Сверьте security и транспорт с серверной конфигурацией, а также ALPN при его
  настройке.
- Проверьте системные дату, время и часовой пояс компьютера.
- `tls.allow_insecure: true` в текущей связанной версии Xray-core не поддержан:
  vclient отклоняет такую конфигурацию, а не отключает проверку сертификата.

## REALITY не подключается

Проверьте, что `pbk` — корректный публичный ключ именно от серверной пары, а
`sid` точно совпадает с одним из `shortIds` сервера. Убедитесь, что `sni`
разрешён серверной конфигурацией. Сверьте `fp` (fingerprint) со значением,
ожидаемым клиентской конфигурацией; по умолчанию vclient использует `chrome`.
Не передавайте клиенту приватный ключ. См. [настройку REALITY](./reality.md).

## `curl` показывает IP клиента вместо IP сервера

Проверьте, что запрос действительно идёт через локальный inbound и что
соединение запущено с корректной VLESS-ссылкой/профилем. Убедитесь, что
маршрутизация отправляет данный трафик в outbound `proxy`, а не `direct`.
Используйте явный SOCKS адрес:

```powershell
curl.exe --socks5 127.0.0.1:1080 https://ifconfig.me
```

## Сборка ломается после обновления Xray-core

Сверьте версию `github.com/xtls/xray-core` в `go.mod` с версией, для которой
проверялись поля JSON и API. Проверьте upstream исходники и changelog для
`infra/conf`, транспорта, DNS и routing; затем запустите `go test ./...`,
`go test ./... -tags integration`, `go build ./...` и `go vet ./...`. Подробный
порядок — в [руководстве разработчика](./development.md).

## `-h` не показывает помощь

Текущая реализация скрывает стандартный вывод `flag.FlagSet` и завершает
разбором с `flag: help requested`. Перечень актуальных флагов приведён в
[руководстве по использованию](./usage.md); для сверки смотрите регистрации в
`cmd/vclient/main.go`.

## Reload завершился ошибкой

При ошибке чтения, валидации или запуска новой конфигурации проверьте лог.
Ошибка на этапе подготовки/валидации не останавливает активный экземпляр.
После ошибки запуска ядро пытается восстановить прежнюю конфигурацию. Для
Windows проверьте URL, метод `POST` и заголовок `X-Reload-Token`; сервер
привязан только к `127.0.0.1:9090`.

## Подписка недоступна

Проверьте доступность URL и формат подписки, затем наличие кэша
`cache/subscription.json` в текущей рабочей директории. Для `-profile` имя
должно точно совпадать с именем одного из профилей подписки. Повреждённый кэш
не используется и требует повторной успешной загрузки подписки.
