# Управление процессом

## Перезагрузка конфигурации

На системах с поддержкой `SIGHUP` сигнал перечитывает профиль, подписку, правила
маршрутизации и DNS. Перед передачей конфига ядру выполняются проверки профиля,
правил и полной JSON-схемы Xray. Если подготовка или проверка завершается
ошибкой, работающий экземпляр не останавливается; ошибка записывается в лог.
Если запуск новой конфигурации после успешной проверки не удался, Runner пытается
вернуть предыдущую конфигурацию.

В Windows передайте `-reload-token <секрет>`. Клиент принимает `POST
http://127.0.0.1:9090/reload` с заголовком `X-Reload-Token: <секрет>`.
Без правильного токена endpoint отвечает `401`. Порт фиксирован и слушает только
loopback-интерфейс.

## Подписка

`-sub-url` загружает VLESS-подписку. Необязательный `-profile` выбирает профиль
по имени; если он не указан, берётся первый профиль. `-sub-interval` задаёт
период обновления (по умолчанию `6h`). Последний успешно разобранный список
профилей атомарно сохраняется в `cache/subscription.json`. Если сеть недоступна,
при старте и перезагрузке используется этот кэш. Повреждённый или отсутствующий
кэш приводит к явной ошибке, а не к запуску с фиктивным профилем.

## Системный прокси

На Windows `-system-proxy` включает системный прокси пользователя в реестре
`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`, направляя
HTTP/HTTPS на HTTP inbound, а SOCKS — на SOCKS inbound. Исходные значения
`ProxyEnable` и `ProxyServer` сохраняются и восстанавливаются при штатном
завершении или панике основного цикла. На других ОС флаг не меняет системные
настройки и выводит предупреждение.
