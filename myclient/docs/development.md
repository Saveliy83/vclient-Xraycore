# Разработка

## Требования и проверка

Проект использует версию Go из директивы `go` в [go.mod](../go.mod) и Xray-core
`v1.260327.0`. Перед отправкой изменений выполните из корня проекта:

```powershell
go test ./...
go test ./... -tags integration
go build ./...
go vet ./...
```

В Bash команды те же:

```bash
go test ./...
go test ./... -tags integration
go build ./...
go vet ./...
```

Интеграционные тесты запускают локальное ядро и проверяют конфигурацию и
прослушивающие порты;
для проверки реального внешнего прокси нужен доступный VLESS-сервер и его
параметры.

Для fuzz-теста ссылок VLESS:

```powershell
go test ./internal/config/ -run=^$ -fuzz=FuzzParseVLESSLink -fuzztime=30s
```

В Bash:

```bash
go test ./internal/config/ -run='^$' -fuzz=FuzzParseVLESSLink -fuzztime=30s
```

Обновление golden-файлов генератора Xray:

```powershell
go test ./internal/xrayconf -run TestBuildXrayJSONGolden -update
go test ./internal/xrayconf
```

Флаг `-update` перезаписывает файлы в `internal/xrayconf/testdata/golden/`;
перед использованием проверьте изменения в файлах и запустите тесты без
`-update`.

## Добавление транспорта

1. Проверьте в исходниках именно подключённой версии Xray-core, как имя
   транспорта, настройки и допустимые комбинации security преобразуются из
   JSON в runtime-конфигурацию. Не полагайтесь на поля другой версии.
2. Добавьте поля транспорта в профиль и JSON-формат в `internal/config`, если
   транспорт требует дополнительных параметров. Опишите обязательные поля и
   ограничения в `Validate()`.
3. Обновите парсер `vless://`, если параметры транспорта передаются в ссылке.
   Неизвестные параметры и некорректные значения должны обрабатываться
   согласованно с текущим парсером.
4. Добавьте генерацию `streamSettings` в `internal/xrayconf` и явно отклоняйте
   несовместимые сочетания либо возможности, отсутствующие в используемой
   версии Xray-core.
5. Добавьте табличные тесты валидации, golden-тест конфига и integration-тест
   при возможности запустить транспорт локально.
6. Обновите `docs/transports.md`, `docs/profile-format.md` и
   `docs/test-matrix.md`. Затем запустите unit, integration, build и vet.

Сохраняйте совместимость существующих профилей и не меняйте несвязанные
документы или настройки без необходимости.
